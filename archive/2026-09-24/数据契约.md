# 蓝色大肥鱼 · AI 娘表情包站数据契约

版本：`v0.4`

## 1. 产品边界

本站收集不同 AI 角色的二创表情包，支持通过 GitHub Issue 投稿。前端不展示完整 tag 分类列表，tag 只作为搜索依据。每张作品有独立详情页，评论由第三方服务（GitHub Discussions / Giscus）承载，不进本站数据。

### 2.1 首批 ID 冻结映射（`dist/blue-fish-ids.json`）

```json
{
  "<sourcePath>": { "id": "sticker_bf_001", "slug": "deepseek202609220001" }
}
```

首批导入记录（`dist/data/blue-fish-classification.json`，legacy 形状、以 `sourcePath` 认图）的 **ID 与 slug 冻结映射**：键是清单里的 `sourcePath`，值是 `{id, slug}`。`id` 沿用 `sticker_bf_NNN`，**不重编号**；`slug` 一经发布同样冻结。为什么必须冻结：`id` 是评论串（`sticker-<id>`）和将来迁数据库的钥匙，`slug` 是已经发出去的 URL，两者被重算一次，旧评论和外链就断一次。路线图 1C（数据库迁移）的前置条件「冻结首批 ID」由本文件关闭。

映射由 `tools/prepare_works.mjs` 写入，**幂等、可重跑**：已有条目永不改写，只补缺；`tools/generate_work_pages.mjs` 与 `tools/build.mjs` 只消费、不改写。首批清单会被仓库外导入流程重新生成，但**本映射不受影响**——这正是把它独立成一份文件、而不是写回清单的原因。

### 2.2 首批编辑叠加层（`dist/data/blue-fish-editorial.json`）

```json
{
  "<sourcePath>": {
    "categoryIds": ["comic"],
    "commentary": "四格讲完一整出戏……"
  }
}
```

首批记录的**分类与第一人称评价**：键同样是清单里的 `sourcePath`，覆盖 `categoryIds` 与 `commentary` 两个字段。

为什么另开一份、而不是写回 `dist/data/blue-fish-classification.json`：那份 raw 清单会被仓库外导入流程重新生成，写在里面的编辑结论会被冲掉；而叠加层是本站自己的复核结论，必须留下来——和 §2.1 的冻结映射同一个道理。站点仓 `tools/build_site_snapshot.mjs` 归一记录时按 `sourcePath` 取它；**没有叠加层的条目退回 `["meme"]` 兜底**。

投稿与站长自用两类记录的这两个字段直接写在各自的 `works.json` 里，不经过叠加层。

## 3. 字段定义

| 字段 | 类型 | 必填 | 生成方式 | 说明 |
|---|---|---:|---|---|
| `id` | string | 是 | 系统生成 | 全局唯一 ID，不使用文件名作为 ID；数据主键与评论串的钥匙，URL 不用它（用 `slug`） |
| `slug` | string | 是 | 系统生成 | 详情页 URL 用（`works/<slug>`），公式 `<characterId><YYYYMMDD><NNNN>`（角色 ID 小写 + 收录日期 + 当日该角色 4 位序号，按收录时间升序编）；**与 `id` 解耦，一经发布即冻结**，不许重算（首批见 §2.1） |
| `name` | string | 是 | 投稿者填写 | 图片展示名称 |
| `description` | string | 否 | 投稿者填写 | 简短描述，用于搜索和图片替代文本 |
| `commentary` | string | 否 | 视觉复核 / 维护者撰写 | 详情页正文段的「蓝色大肥鱼第一人称评价」（2026-09-25 起取代原先的第三人称长尾模板，见站点仓 `tools/generate_work_pages.mjs` 的 `renderBodyParagraph`）。逐张看图后手写，40–90 汉字，第一人称，必须扣住该图的画面；缺此字段时详情页退一句通用第一人称兜底 |
| `path` | string | 是 | 系统生成 | 原图访问地址（GitHub Raw URL；上游首批与本仓库投稿按记录区分仓库） |
| `thumbnailPath` | string | 是 | 系统生成 | 列表缩略图（约 480px 派生 WebP，由 `tools/generate_image_derivatives.py` 生成） |
| `fullPath` | string | 是 | 系统生成 | 详情显示图，最长边 ≤1280px 派生 WebP，由 `tools/generate_image_derivatives.py` 生成 |
| `format` | string | 是 | 系统生成 | png、jpg、jpeg、gif、webp、apng 等 |
| `mimeType` | string | 是 | 系统生成 | 文件 MIME 类型 |
| `isAnimated` | boolean | 是 | 系统生成 | 是否为动态图片 |
| `width` | integer | 是 | 系统生成 | 图片宽度，单位 px |
| `height` | integer | 是 | 系统生成 | 图片高度，单位 px |
| `fileSize` | integer | 是 | 系统生成 | 文件大小，单位 byte |
| `sha256` | string | 是 | 系统生成 | 用于检测重复文件 |
| `characterId` | string | 是 | 投稿者选择 | 角色 ID |
| `tone` | string | 是 | 系统生成 | 卡片占位底色键，取值对齐 `--art-<tone>-*` Token 组；新角色可先用 `other` |
| `symbol` | string | 否 | 系统生成 | 图片加载占位字形，可为空字符串 |
| `categoryIds` | string[] | 否 | 系统初分 / 维护者调整 | 分类 id 数组，引用分类记录（§4.1），可空。**初分规则**（`tools/prepare_works.mjs`）：id 形如 `sticker_op_*`→`illustration`，名含 立绘 / 设定 / 三视图→`setting`，其余→`meme`；首项是详情页的类型词 |
| `tags` | string[] | 否 | 投稿者填写 | 自由 tag，不做前端分类按钮 |
| `submitter` | object | 是 | 投稿者填写 | 提交者信息 |
| `origin` | object | 是 | 投稿者填写 | 内容来源信息 |
| `license` | object | 是 | 投稿者确认 | 收录和下载授权状态 |
| `status` | string | 是 | 系统/管理员 | 审核和展示状态 |
| `createdAt` | datetime | 是 | 系统生成 | 首次收录时间 |
| `updatedAt` | datetime | 是 | 系统生成 | 最近修改时间 |

## 4. 角色记录

```json
{
  "id": "deepseek",
  "name": "DeepSeek娘",
  "aliases": ["蓝色大肥鱼", "鲸鱼娘"],
  "status": "active",
  "inSubmissionForm": true
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 角色 ID，作品记录只存它 |
| `name` | string | 展示名称，可修改 |
| `aliases` | string[] | 别名，进搜索 |
| `status` | string | 状态 |
| `inSubmissionForm` | boolean | 是否出现在投稿表单的角色下拉 |

权威清单是 `dist/characters.json`。角色名称可以修改，图片只保存 `characterId`。搜索角色别名时仍能找到对应图片。

`inSubmissionForm: false` 的条目（如 `owner-picks` 站长自用）借角色结构做分类但不进投稿下拉；前端筛选里的 `all` 是 UI 哨兵，不在清单里。

### 4.1 分类记录

```json
{
  "id": "complaint",
  "name": "吐槽疑问",
  "description": "吐槽、质疑、发问",
  "status": "active"
}
```

权威清单是 `dist/categories.json`，形状为 `{ "id", "name", "description", "status" }`。作品记录经 `categoryIds` 引用。**分类体系重建 = 只改清单与本节**，不动代码；构建（`tools/build.mjs`）对引用完整性做断言。

现行枚举（2026-09-25 起）：

| id | 名称 | 判据 |
|---|---|---|
| `meme` | 梗图 | 单格、以玩梗 / 反应 / 吐槽为目的的聊天用图 |
| `illustration` | 插画 | 单格、有场景构图的完整画作 |
| `setting` | 设定图 | 立绘、三视图、设定稿、物料设定 |
| `comic` | 漫画 | 画面上 ≥2 个分格 / 分镜，格间有叙事或对话推进 |

判定顺序是**先数格子**：多格 → `comic`；否则立绘 / 设定稿 → `setting`；否则有场景构图的成品画 → `illustration`；其余 → `meme`。

口径说明：`tools/prepare_works.mjs` 与站点仓 `tools/build_site_snapshot.mjs` 里各自有一份 `categoryIds` 启发式，那只管**新条目入库时的兜底**，判不出多格分镜，因此**永远不会给出 `comic`**——`comic` 只来自看图复核后写进清单的结果。存量 191 件已于 2026-09-25 逐张视觉复核重分类，结果冻结在清单里。

## 5. 来源类型

`origin.type` 支持：

```text
self-created       自己创作或生成
author-submitted    原作者本人投稿
internet-found      网络整理
community-created   社区成员创作
unknown             来源不明
```

`sourceUrl` 是可选字段。自己生成或没有公开来源的内容可以填写 `null`，不能因为没有链接而无法投稿。

## 6. 授权类型

```text
submitter-permission  投稿者确认允许收录和下载
author-permission     原作者明确授权
cc0                   CC0
cc-by                 CC BY
cc-by-nc              CC BY-NC
unknown               授权状态不明
removed                已撤下
```

投稿者必须确认：自己有权投稿，或本站收到版权投诉时可以联系投稿者协助处理。

## 7. 状态

```text
pending    等待审核
published  已公开展示
rejected   审核拒绝
removed    已下架
```

只有 `published` 记录进入公开前端数据。

## 8. 搜索契约

默认使用模糊搜索，不要求用户输入完整词语，也不区分大小写。

搜索范围：

- `name`
- `description`
- `tags`
- 角色 `name`
- 角色 `aliases`
- 投稿者名称

搜索前统一标准化：去除大小写差异、空格、下划线和短横线。

示例：搜索“`大肥鱼`”可以命中“蓝色大肥鱼”“DeepSeek娘大肥鱼”和“吃白饭的大肥鱼”。

## 9. 前端筛选与排序

前端支持：

- 关键词模糊搜索
- tag 模糊搜索
- 角色筛选
- 格式筛选
- 静态/动态筛选

排序支持：

- 最新收录
- 最早收录
- 名称正序
- 名称倒序
- 文件大小
- 随机

暂不实现情绪、场景、颜色等复杂分类，也不展示 tag 云或完整 tag 按钮列表（分类轴的枚举与 `categoryIds` 见 §4.1：数据边界已就位，分类 UI 随「分类体系重建」落地）。排序不包含任何热度维度（见 §11）。

列表按批次加载：首批 24 条，滚动接近底部时继续追加，直到当前筛选结果全部展示完。
因此前端会一次性持有全部 `published` 记录并按筛选结果分页，不要求接口分页；
若将来记录量级变大，再把这个批次加载改成真正的分页接口（`limit` / `offset`）。

## 10. 投稿校验

自动校验：

- 文件格式是否受支持；
- 文件大小是否超过限制；
- 是否存在相同 `sha256`；
- `characterId` 是否能在 `characters.json` 中解析；
- `categoryIds` 是否都能在 `categories.json` 中解析；
- `name` 是否为空；
- `tags` 是否为字符串数组；
- 图片是否能正常解析；
- 是否包含可执行文件或异常扩展名。

投稿通过自动校验后进入 `pending`，管理员审核后才变为 `published`。

## 11. 聚合统计与热度边界

`v0.2` 起移除 `downloadCount` 字段及其排序；`v0.4` 起接入 Google Analytics 4，用于聚合的网站访问、来源、设备与性能分析。

**GA4 统计不属于作品数据契约**：不把页面访问、事件或用户标识写进作品记录，不基于它生成作品热度分、排行榜或曝光权重。广告个性化、Google Signals 与广告存储关闭；Google Analytics 可能设置第一方分析 Cookie，公开口径见 README 与关于页。

仍然不存储、不展示：

- 单作品浏览量、点赞、收藏、分享、下载次数；
- 任何进入作品清单的热度字段；
- 任何形式的作品热度分或排行榜。

发现作品仍使用：按角色浏览、分类与 Tag 检索、随机排序。

## 12. 评论

评论不属于本站数据契约：

- 评论内容托管在第三方服务（默认 Giscus，基于 GitHub Discussions）；
- 讨论串与作品的对应关系由前端按 `sticker-<id>` 作为 term 建立，不需要在作品记录里存字段；
- 本站不保存评论、不保存评论者身份，也不把评论数量写回作品记录；
- 切换评论服务只影响前端，作品记录不变。
